# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**zipgo** — a minimal static site host written in Go. It embeds Caddy as a library, discovers domains and subdomains from a local domains folder (default `.zipgo/`), and serves them over HTTPS (domain mode) or HTTP on a single localhost port (localhost mode).

Where this is going is defined in [GOAL.md](GOAL.md) — read it before proposing features.

## Commands

```bash
make build          # Compile binary (also regenerates install scripts)
make run-local      # Build + run on localhost (no sudo, no domain needed)
make run            # Build + run with real domain (needs sudo, ports 80/443)
make run-prod       # setcap + run in domain mode
make format         # Run gofmt
make clean          # Remove binary
make build-install-scripts  # Regenerate install/{linux,macos,windows}.sh from parts
```

CLI subcommands: `zipgo serve` (default), `zipgo deploy` (rsync a local dir to a remote zipgo host over SSH, creating the trailing-dot subdomain folder tree and snapshotting the site's prior content into `.zipgo-versions/` first — see `internal/deploy`), `zipgo ls`/`zipgo info` (read-only SSH inspection of what's deployed on the remote target, `--json` for machine-readable output — see `internal/remote`), `zipgo rollback <host> [version]` (swap a past `.zipgo-versions/` snapshot back into place, `--list` shows the history — see `internal/remote/rollback.go`), `zipgo doctor` (lint the local domains folder — see `internal/doctor`), `zipgo off|on <host>...` (switch a deployed site off — 410 Gone, nested subdomains included — or back on, over SSH — see `internal/deploy/switch.go`), `zipgo password set|status|remove|hash` (put a site behind zipgo's login page, over SSH or `--dir` — see `internal/password` and `internal/gate`), `zipgo admin set|remove <host>` (make a folder a domain's back-office — see `internal/admin`), `zipgo flag [ls|on|off|add|rm] <host> [name…]` (a site's feature flags, over SSH or `--dir` — see `internal/flags`), `zipgo enable|disable|status` (systemd user service — **not** the per-site switch; that name was taken, hence `off`/`on`), `zipgo version`, `zipgo help`.

### Remote inspection (`internal/remote`)
`ls`/`info` shell out to `ssh` (GNU coreutils assumed on the remote, as the existing `find -printf`/`date -r` calls already did). `siteDirs` finds every folder under the base and keeps the ones `deploy.HostFromRemote` maps back to a host; `stat` then runs **one** generated script (`statScript`) over exactly those folders, printing a tab-separated record per site that `parseSites` (pure, table-tested) turns into a `Site`. `Site` is the single source of truth for both the human output and `--json`: `Type` (`static`/`spa`/`proxy`/`redirect`), `Enabled` and `Protected` are recomputed the way `internal/builder` routes the site — `Enabled` **with the cascade** (`cascade()`: a site under a parent whose own config is off is off too, `OffBy` = the nearest such parent, decided by folder nesting, not host suffix; `SiteFor` therefore stats the host's parent folders along with it) — — SPA = `index.html` + a bundle dir, proxy = a `.zipgoconfig.json` `rewrite`, redirect = a `redirect`, protected = a `basicAuth` (reported as a bool; the hashes are never emitted) — so keep `bundleDirs` in sync with `internal/sites`, and an unreadable config surfaces as `ConfigError` rather than being dropped. `Size`/`Files` **prune nested trailing-dot folders and the `.zipgo-versions` history folder** (sites of their own, and backups — not the site's current content), so an apex is not the sum of its whole domain. `--json` shapes: `ls` → `[]Site`, `ls <host>` → `[]Entry` (that folder's children), `info <host>` → one `Site`. The human `ls` doesn't run `statScript` (its per-folder `find` makes it ~3 s on raspy2); it reads only the configs (`configScript` → `parseSwitches`) to mark switched-off sites `⏸ off` / `⏸ off through <parent>`.

### On/off switch (`zipgo off` / `zipgo on`, `internal/deploy/switch.go`)
The per-site switch is the existing `"enable"` key, edited over SSH. It lives in `deploy`, not `remote`, because a deploy must honour it (and `remote` already imports `deploy`). `inspect` runs **one** script (`stateScript`) that prints a record per folder — the host's parents (`ParentDirs`, outermost first), itself and, for `off`/`on`, every nested trailing-dot folder — with its base64 config; `parseState` keeps only real site folders (`HostFromRemote`). `SetEnable(raw, on)` is the pure edit: it parses with `sites.ParseConfig` first (a config the server rejects is refused, never rewritten), keeps keys in **file order** (`parseObject`/`marshalObject`, not a Go map), writes `"enable": false` in place or as the first key, and on `on` drops it — returning nil (delete the file) when nothing is left. `writeConfig` writes via `mktemp` **in the domains root** (same filesystem, outside every site, so a half-written file — maybe a password hash — is never served) + `mv`, so the watcher never reloads a half-written file (a malformed config aborts the whole reload); it `mkdir -p`s the site folder, so `zipgo password set` can lock a site before its first deploy. `runRemote` is a variable: the tests swap it for `sh -c`, so the very scripts that go over SSH run against a temp folder.

`deploy.Run` reads the same state in the SSH hop that does the `mkdir` (no extra round trip). **A deploy ships files, never server state**: when the host is off by its own config, **locked** (`password`/`basicAuth` — `sites.Locks`), has a **`flags` block** or has an unreadable config (`keepConfig`), rsync gets `--exclude=/.zipgoconfig.json` (an excluded file is also safe from `--delete`) and `mergeKept` then publishes the build's own config, if any, through `KeepServerState` (pure, table-tested): `"enable": false` kept, every server lock put back in place of the build's own (a build can't unlock a site or change its password), and the server's `flags` merged into the build's by `MergeFlags` (the server's switch wins; a flag the build writes as an object brings its description/paths; a new flag lands as shipped; server-only flags stay). When it is off through a parent, the files ship and the output says so, and the `✓ https://…` line becomes `⏸ stays off …`. `remoteSpec` (the rsync destination) is a variable too, so `lock_test.go` runs a real `Run` against a temp folder.

### Deploy history & rollback (`.zipgo-versions`)
Before it overwrites a site, `zipgo deploy` snapshots that site's **current own content** into a hidden `<site>/.zipgo-versions/<UTC-stamp>/` folder (`deploy.snapshot`/`snapshotScript`, run over SSH), keeping the newest `--keep N` (default `deploy.DefaultKeep` = 5; `--no-history`/`--keep 0` disables it). The snapshot rsync excludes `.zipgo-versions`, the site's `.zipgoconfig.json` and nested `*.` subdomain folders — the same content boundary the deploy mirror and `remote` sizing use — and is a no-op when there is no real prior deploy to capture (folder absent, or no `index.html`). `zipgo rollback <host> [version]` (`internal/remote/rollback.go`) lists (`Versions`/`parseVersions`, pure/table-tested) or restores a snapshot; restoring first snapshots the current live content (so a rollback is itself reversible), then rsyncs the chosen snapshot back over the live folder (`restoreScript`), again never touching history, child subdomain sites or the live `.zipgoconfig.json` — **a rollback ships content, never server state**, like a deploy: a site that is off stays off, a lock stays, flags keep their switch. The name `.zipgo-versions` is `sites.VersionsDirName` — **the single source of truth**; it is referenced by `internal/deploy` (snapshot + the `versionsExclude` rsync guard that keeps `--delete` from wiping history), `internal/builder` (added to the file_server `hide` list so snapshots are never served), and `internal/remote` (statScript prune + rollback). Discovery ignores it for free — `sites.Discover` skips dot-prefixed dirs, so a snapshot folder is never mistaken for a subdomain or content, and `HostFromRemote` rejects it (no trailing dot) so `ls` never lists it as a site.

### Password-protected sites (`internal/gate`, `internal/password`)
A `.zipgoconfig.json` `"password": {"hash", "title", "sessionDays"}` block puts the whole site behind a login page. **`internal/gate`** is a custom Caddy module, `http.handlers.zipgo_password` (registered in its `init`; `builder` imports it, so it is always linked): no valid session → `401` + the one generic login page (`page.go`, only the title varies; `no-store`, `noindex`, strict CSP) on every path; `POST <prefix>/__zipgo/login` checks bcrypt and sets a `__Host-zipgo_session` cookie `"<expiry>.<mac>"`; `<prefix>/__zipgo/logout` clears it; a GET/HEAD carrying `?__zipgo_pwd=<password>` (`UnlockParam`, every locked site, no config) is checked like the form (same throttle) and 303s to the same URI minus that param (`withoutParam` keeps the other params' order/spelling) — with a session already, it just redirects, no bcrypt. The MAC key is `HMAC(server key, host, hash)`: the server key (`KeyFile()` = Caddy's `AppDataDir()/zipgo/session.key`, 0600, created on first use) makes cookies unforgeable even to someone who read the config, the host scopes them, and the hash — a new salt on every `set` — makes **rotation log everyone out**. Sessions are renewed once they are a day old (`renewAfter`), so a regular visitor never sees the page again. Wrong passwords are throttled per client IP (10/min) and per site (60/min) in a package-level registry keyed by host — **not** on the handler, because Caddy re-provisions every handler on each reload, i.e. on every deploy. An unusable hash fails **closed** (logged, nobody gets in) rather than failing provisioning, which would make Caddy reject every site's config. Localhost mode passes `prefix` + `insecure` (plain-HTTP cookie, `Path=<prefix>`).

`builder.lockHandlers` puts the gate before `basicAuthHandler` (both run when both are set — doctor warns); `siteHandler(s, host, prefix)` and `guard(route, s, host, prefix)` use it, so the site and its `sub-domains-meta` are both covered. A password site is **HTTPS-only** (`httpAllowed` ignores `allowHttp`: the cookie is `Secure`), gets `lockedHeaders` (`Cache-Control: private, no-cache`, `X-Robots-Tag: noindex, nofollow`) under its own `headers` via `siteHeaders`, and `childMeta` drops **every protected child** (`Config.Protected()` = password or basicAuth) from its parent's public feed. Domain fronting needs nothing special: zipgo routes by Host, and the gate is inside the host's route.

**`internal/password`** backs `zipgo password set|status|remove|hash`: a `Store` (`Local{Base}` for `--dir`, `Remote{Target}` over `deploy.ReadConfig`/`WriteConfig`) holds the site's config; `SetPassword` swaps the `password` key and keeps every other one. The password is read from a no-echo prompt (twice), `--stdin` or `--generate`, and bcrypt-hashed **client-side** at `password.Cost` (12, ~0.3 s per login on a Pi 5) — only the hash travels. The target resolves like deploy's (`--ssh` > package.json `zipgo.target` > `.zipgo.json`), in `main.runPassword`.

### Feature flags (`internal/flags`, `sites.Flag`, `deploy/flags.go`)
A `.zipgoconfig.json` `"flags"` block — `name → bool | {"on", "description", "paths"}` (`sites.Flag.UnmarshalJSON` takes both; an object without `on` is **off**) — declares switches the site's own code reads at runtime. `ParseConfig` validates names (`InvalidFlagName`: a letter + 63 of `[A-Za-z0-9_-]`) and paths (`InvalidFlagPath`: a plain prefix, no globs, no `.`/`..`, not `/`), a hard error like `headers`. **`internal/flags`** is a Caddy module, `http.handlers.zipgo_flags` (registered in its `init`; `builder` imports it): `builder.flagsHandler` emits it for every non-admin site with a `flags` block (`Config.HasFlags()` — even empty) with `flags` (name → on), `closed` (the normalised paths of the **off** flags) and, in localhost mode, `prefix`. `siteHandler` puts it **after the locks** and before the site's handler, so on a locked site the endpoint and the 404s are behind the login page. It answers `<prefix>/__zipgo/flags.json` (`sites.FlagsPath`) → `{"flags": {…}}` with `no-store`, and a plain 404 on a request whose `path.Clean`ed path is a closed prefix or under it — before files, the SPA fallback or a proxy. Everything else goes to `next`. No state: a flip is a config edit + watcher reload.

The edits are pure and in `deploy/flags.go` (they need `parseObject`/`marshalObject`, and the deploy merge lives there): `SetFlag` (refuses an unknown name; a bool stays a bool, an object gets `on` set in place), `DeclareFlag` (create/update from a `FlagSpec`, the switch kept unless given; written as a bare bool while it has no description/paths), `RemoveFlag` (the block stays, even empty), `MergeFlags`. The back-office (`admin.SetFlag`, `POST api/flag {id,name,on}`, rows carry `flags`) and the CLI (`flags.ParseArgs`/`Run` over a `password.Store`, wired in `main.runFlag`) both go through them. Projects declare their flags in the build's own `.zipgoconfig.json` (Vite: `public/`) and treat a non-JSON answer as "all off" on a real host (all on in dev/localhost) — see Ballance's `web/src/flags.ts`.

### Back-office (`internal/admin`)
A folder whose `.zipgoconfig.json` has `"admin": true` (+ a `password`, which `zipgo admin set` — `internal/password/admin.go` — writes in the same file) serves a page managing **the site its folder is nested in** and every subdomain under it: `gabvdl.xyz/admin./` → `admin.gabvdl.xyz` manages the whole domain. **`"admin": "all"`** (`zipgo admin set <host> --all`, or `--scope all|site`; a `set` without either keeps the scope) manages **every domain in the domains folder** instead. `sites.Config.Admin` is a `sites.AdminScope` (`""` / `AdminSite` = JSON `true` / `AdminAll` = `"all"`; its `UnmarshalJSON` refuses anything else) — test it with `cfg.IsAdmin()`, never as a bool. For `AdminAll` `builder.adminHandler` emits `scope: "all"` + `domains_dir` (no `root`/`root_host`/`root_path`) and the handler's `roots()` re-reads the domains with `config.ReadDomains` on every request (one `root` per domain, `Path` `/<domain>` in localhost mode); a row's ID is then **`<domain>/<folder path>`** (`gabvdl.xyz/dev./card-editor.`, the domain row is `gabvdl.xyz`) and `locate` splits it back — the first part must be one of those domains — before calling the unchanged `Switch`/`SetLock`/`SetFlag` with the root's folder. `/api/sites` carries `roots` (and `scope`) in both modes (`[""]` for a site's back-office); `Sizes` is cached per root. The page (`app.js`) keys everything off `state.all`/`state.roots`: domain rows are folded group heads with an `n sites · m off` meta line, `#domains` chips narrow the page (stored in `localStorage` `domain`), expanded rows are stored per scope (`open` / `open:all`), and the list view groups by domain. `doctor` allows an apex `"all"` back-office (it manages no parent). `internal/admin` is a Caddy module, `http.handlers.zipgo_admin` (registered in its `init`; `builder` imports it): `builder.adminHandler` emits it with `root` (the parent folder), `root_host`, `self` (its own folder), `tmp_dir` (the domains folder) and, in localhost mode, `prefix`/`root_path`; `siteHandler` puts the gate in front as for any locked site, and **without a password `adminRefusal` (403) is emitted instead — fail closed**, the handler never appears. It is **not a second source of truth**: no state, every request re-walks the tree (`List`, resilient: a malformed config is reported as `configError` rather than aborting like `sites.Discover`), and every write is the same edit the CLI makes — `Switch` = `deploy.SetEnable` (the `zipgo off` edit), `SetLock` = `password.SetPassword` (title/sessionDays kept) — written through a temp file in the domains folder + rename (`writeFile`), `chownLike` the folder when running as root (Docker), serialised by `switchMu`. Sites are addressed by **folder ID** (`dev./card-editor.`, `resolve` refuses `..`, hidden and non-trailing-dot parts), never by host (a host can be spelled by two folder trees). The back-office can't switch or re-password itself, and is **exempt from the cascade** — `sites.Discover`, `remote.cascade`, `doctor.walk`, `admin.List` and `deploy.liveNested` all skip it — so switching the domain off leaves the way back on. `builder.childMeta` never lists it. API (relative to the page, so localhost prefixes work): `GET api/sites`, `GET api/sizes` (a full walk, cached 1 min in `sizesCache`), `POST api/switch {id,on}`, `POST api/password {id,action:set|generate|remove,password}` — POSTs need JSON + same origin (`sameOrigin`: `Sec-Fetch-Site`, `Origin`, content type), on top of the gate's `SameSite=Lax` cookie. The UI is `internal/admin/ui/` (embedded: vanilla JS, no build step, tree + list views, Undo toast, details `<dialog>` for the password), served with a strict CSP (`script-src 'self'`, so no inline script/style attributes — the JS sets `--d` via CSSOM).

### Config-driven deploy (`internal/zipconfig`)
`zipgo deploy`, `ls` and `info` resolve their target and source folders from two config files so they don't have to be repeated (`internal/zipconfig`, both found by **ascending** the dir tree from the cwd):
- **Root** `.zipgo.json` → `{ "target": "user@host:/base", "targets": {"name": "..."} }` — the default `--ssh` destination.
- **Project** `package.json` `"zipgo"` field → `{ "deploy": {"<host>": "<srcDir>"}, "target": "<override>" }` — maps each host to its local build folder (paths relative to package.json).

`deploy.ParseArgs` is **lenient** (src/-d/--ssh all optional); `deploy.Resolve(&opts, proj, root)` is the pure function that fills `opts.SSH` + `opts.Jobs []Job{Host,Src}` from flags+config and validates, then `deploy.Run` iterates the jobs. Precedence: `--ssh` > project `target` > root `target`; `-d` hosts > all map keys; positional dir > map entry. The fully-explicit `dir -d host --ssh …` form is unchanged (back-compat). `deploy.HostFromRemote` is the inverse of `RemoteDir` (folder path → host), used by `ls`.

`deploy.rsyncArgs(o, src, dest, dryRun)` centralises the rsync flag mapping (mirror `--delete`, the `*./` subdomain-protection auto-exclude, user `--exclude`s, and — in dry-run — `--dry-run --itemize-changes`). Under `-n/--dry-run`, `Run` runs no remote `mkdir`, captures rsync's itemized output and feeds it through `ParseItemized`/`WriteSummary` (`internal/deploy/summary.go`, pure + table-tested) to print a per-host **added/replaced/deleted** summary before anything is touched — the nested subdomain guard means a mirror preview never lists a child site as a deletion. `--prune` is a `ParseArgs` alias for the default `--delete`.

## Architecture

### Discovery model
The folder tree *is* the routing table. Inside the domains folder, each subfolder whose name contains a dot is a **domain** (others are ignored). Within a domain folder:
- the folder root itself is the **apex** site (`yourdomain.com`)
- any subfolder whose name **ends in a dot** is a **subdomain** — `docs.` → `docs.yourdomain.com` — applied **recursively** (`docs./api.` → `api.docs.yourdomain.com`). Multi-dot names map directly (`foo.bar.` → `foo.bar.yourdomain.com`).
- folders that don't end in a dot are ordinary content of their parent site (served as paths); subdomain folders are hidden from the apex's directory listing via a `*.` file_server hide.

### Startup flow (`main.go`)
1. Resolves the domains folder from `ZIPGO_DOMAINS_FOLDER` (default `.zipgo`); `config.ReadDomains` lists valid domain folders
2. No domains, or `ZIPGO_LOCALHOST=1` → localhost mode; otherwise domain mode
3. Calls `sites.Discover()` per domain + `builder.Build*Config()` to generate a Caddy JSON config in memory
4. Calls `caddy.Run(cfg)` — no Caddyfile on disk, config is entirely in-memory
5. Watches the domains folder; on filesystem changes it calls `reload()` which re-runs steps 3–4

### Internal packages
- **`internal/sites`** — recursively walks a domain folder; `Site` holds a leaf-first `Labels` chain (empty = apex) and `Disabled`, set during the walk when the site's own config **or any parent's** says `"enable": false` (the cascade). Use `Site.Off()` (= `Disabled || !Config.Enabled()`), never `Config.Enabled()` alone, to ask whether a site is switched off — `Config.Enabled()` only answers for the folder's own file. Helpers: `Host(root)`, `IsApex()`, `LocalhostPath(domain)`. Detects SPAs when `index.html` + one of `assets/`, `static/`, `_next/`, `dist/` is present (`DetectSPA`), and a custom 404 page when the folder holds a `404.html` (`DetectNotFound` → `Site.NotFoundPage`, kept as spelled on disk; `HasNotFoundPage()` gates it on the site being static — see below). `DetectSPA`/`DetectNotFound` are exported so `doctor`, which re-walks the tree itself, agrees with discovery instead of re-implementing the rules
- **`internal/admin`** — the back-office module (see *Back-office* above)
- **`internal/flags`** — the feature-flags module and the `zipgo flag` CLI (see *Feature flags* above)
- **`internal/builder`** — constructs the Caddy JSON config; `BuildLocalhostConfig` for HTTP-only path routing, `BuildConfig` for HTTPS host routing. TLS subjects are exact hosts (correct for nested/multi-dot subdomains). Each site gets one of: its normal route (`served` = not off + `hasContent`), a **410 route** (`Gone` = off + `hasContent` — a folder that only holds subdomains stays unrouted when off, so switching it off never makes Caddy request a cert for a host that was never live → `goneHandler`: security headers + `Cache-Control: no-store` + a static `GoneBody` page; the host **stays in the TLS subjects** so the 410 is reachable over HTTPS), or nothing (an empty holder folder, on or merely under an off parent)
- **`internal/config`** — `ReadDomains` scans the domains folder for valid domain subfolders (must contain a dot; malformed are skipped)
- **`internal/service`** — systemd user-service install/remove/status
- **`internal/doctor`** — backs `zipgo doctor`: lints the domains folder and returns a `Report` of `Finding{Level, Host, Path, Msg, Hint}` (`Warn`/`Error`; `Report.OK(strict)` drives the exit code). It deliberately **re-walks the tree instead of calling `sites.Discover`**: Discover is a hard-fail parser (one malformed `.zipgoconfig.json` aborts the whole reload), whereas doctor must keep going and report *every* problem in one pass. Its `walk` carries `offBy` down the tree so switched-off subtrees are counted as `Disabled` and skipped, like the server's cascade. Checks: missing `index.html` (Error, downgraded to Warn when the folder only holds subdomains — that's the legitimate `gabvdl.xyz/game./` shape; the hint must **not** suggest `"enable": false` there any more, it would switch every child off), an `"enable": true` under a switched-off parent (Warn — the cascade wins), malformed `.zipgoconfig.json`, unknown config keys (a typo'd `"enabled"` is silently ignored by the real parser), invalid domain/subdomain folder names, a dot-containing folder that forgot its trailing dot, an unusable `rewrite` upstream, an unusable `redirect` target / `redirectStatus` (including `redirect` combined with `rewrite`, or a redirect over a folder that still has an `index.html`), a `basicAuth` password that isn't a bcrypt hash (`invalidBcrypt` — a plaintext value is an Error: Caddy only ever compares hashes, so it locks everyone out *and* commits a secret), a `password` block (`checkPassword`: unusable hash = Error "nobody can log in", unknown inner keys, `sessionDays` out of 1–400, `password`+`basicAuth`, `password`+`allowHttp`), a `404.html` in a site that can never serve it (`checkNotFoundPage` — an SPA, a `rewrite` or a `redirect` site; Warn), and two folders resolving to the same host. Keep `knownConfigKeys` **and** `knownKeyList` in sync when adding a `.zipgoconfig.json` key.

### Subdomain metadata endpoint
Any site that has at least one direct child subdomain (the apex, or a subdomain with nested subdomains) serves a JSON listing at `<host>/sub-domains-meta` (localhost: `/<domain>/<path>/sub-domains-meta`). It maps each direct child's folder name (e.g. `"docs."`) to metadata extracted from that child's `index.html` — `title`, `description`, OpenGraph (`og:*`) tags, favicon `icon`, and custom `zipgo:*` meta properties (exposed under `zipgo`, keyed by the part after the prefix). The JSON is computed at config-build time in `internal/builder` (`childMeta`/`metaRoute`) using `internal/meta` and embedded as a Caddy `static_response`, so it refreshes on every watcher reload. Children one level down only; leaf sites get no endpoint (404).

### Per-site config (`.zipgoconfig.json`)
Any site folder may contain a `.zipgoconfig.json` read at discovery time into `sites.Config` (`internal/sites`, `readConfig`) and attached to each `Site`. A missing file is the zero value (defaults); a malformed file is a hard error so typos surface. Pointer `*bool` fields distinguish unset from explicit false. Keys: `enable` (false → the site **and its whole nested subtree** answer 410 Gone, keep their certs, and drop out of any parent's `sub-domains-meta`; an `"enable": true` below an off parent cannot override it — `doctor` warns. Gated by `Site.Off()` in `builder.served`/`Gone`/`childMeta`/`hasWww`; written by `zipgo off`), `rewrite` (non-empty → the site is a `reverse_proxy` to that upstream instead of a `file_server`; `builder.proxyHandler`/`proxyDial` turn a `host:port` or scheme URL into a Caddy dial address + TLS transport), `rewritePath` + `rewritePathPassthrough` (prefix the proxied path so a sub-path of the upstream — PocketBase's `/_/` dashboard — is served at the site's root with the URL staying put; `builder.rewritePathRoute` emits a Caddy `rewrite` guarded by a `not`/`path` matcher so the prefix is skipped for a path that already carries it and for the upstream's own root paths. That exemption is load-bearing, not a nicety: the app under the prefix still calls the upstream's root absolutely — PocketBase's dashboard fetches `/api/…` — and prefixing those to `/_/api/…` 404s, so the UI loads but login fails. `sites.NormalizeRewritePath` strips the trailing slash so the prefix concatenates exactly once; the passthrough list defaults to `sites.DefaultRewritePathPassthrough` (`/api`) and an explicit `[]` means "prefix everything"), `redirect` + `redirectStatus` (non-empty → the site is a `static_response` redirect instead of a `file_server`; `builder.redirectHandler`/`redirectLocation` append `{http.request.uri}` when the target is a bare origin so paths and queries survive, and use the target verbatim when it carries a path; the status defaults to `sites.DefaultRedirectStatus` = 302), `allowHttp` (true → the host is also served on `:80` via `httpRoutes` instead of the catch-all HTTPS redirect; no effect in localhost mode), `headers` (a name → value map merged into the security-headers handler — see below), and `basicAuth` (a `username → bcrypt hash` map → the site is served behind HTTP basic auth) and `password` (zipgo's login page — see *Password-protected sites* above; `zipgo password` writes it), and `admin` (true → the folder is the back-office of its parent — see *Back-office* above; `zipgo admin set` writes it with a password), and `flags` (feature flags — see *Feature flags* above), and `browse` (true → a folder of the static site that has no `index.html` gets a directory listing; **off by default** — `fileHandler` only emits Caddy's `browse` when `Config.BrowseEnabled()`, and never for an SPA).

`builder.unguardedSiteHandler` chooses redirect vs proxy vs file (in that precedence) and hides `.zipgoconfig.json` from the file_server; `builder.siteHandler` then wraps *whatever that produced* in `basicAuthHandler`'s Caddy `authentication` handler, so the credential check runs before files, SPA fallback, a proxied upstream or a redirect are reached, and `builder.guard` prepends the same handler to a protected site's `sub-domains-meta` route so it can't leak the child listing of a password-protected site. Basic auth is per-site: a child subdomain is a separate site and needs its own `basicAuth`. The `authentication` handler is only registered because `main.go` imports `caddyhttp/caddyauth` — Caddy rejects the whole config at load time if that import is dropped. The file watcher hot-reloads config edits like any other change.

**When adding a key**, three places must move together: the `sites.Config` struct, `doctor.knownConfigKeys` (+ its `knownKeyList` hint — an unlisted key is reported as an ignored typo), and the README's per-site-config section.

### Custom 404 page (`404.html`)
A static site with a `404.html` in its folder serves it as the body of its 404s instead of Caddy's plain-text default — no config key, the file's presence *is* the config (`sites.NotFoundFileName`). `builder.fileHandler` attaches `errors` routes (`notFoundErrors`) to the site's subroute: a Caddy `subroute` runs its `errors.routes` when an inner handler returns an error, so a `file_server` 404 is matched (`{http.error.status_code} == 404` — only a 404, so a 403 or 500 is still Caddy's), rewritten to the page and re-served by a second `file_server` carrying `"status_code": "404"`. That `status_code` is the load-bearing bit: without it the page would go out as a **200 soft-404** and crawlers (and `curl -f`) would think the URL exists. The error routes live *inside* the subroute that `siteHandler` wraps in `basicAuthHandler`, so a protected site's 404 page stays behind its password.

`sites.HasNotFoundPage()` decides whether the route is emitted at all: only for a static site. An SPA already rewrites unknown paths to `/index.html` (a 200 — it never 404s), and `rewrite`/`redirect` sites never reach the file server, so in those folders the file would be dead weight — `doctor` warns rather than letting it look like it works. The page is resolved against the site's own root, so a subdomain does not inherit its parent's, and in localhost mode the rewrite is root-relative (not prefixed).

### Framing / clickjacking policy (`zipgo:authorized-origins`)
Every static route gets a security-headers handler (`securityHeaders` in `internal/builder`). By default it sends `X-Frame-Options: SAMEORIGIN`, so a page cannot be embedded in a frame from another origin. A site can opt into cross-origin embedding by declaring `<meta property="zipgo:authorized-origins" content="...">` in its `index.html`: the builder (`authorizedOrigins`) reads it and, when present, drops `X-Frame-Options` and instead emits `Content-Security-Policy: frame-ancestors 'self' <content>`. The content is a space-separated list of CSP `frame-ancestors` source expressions (host patterns supporting `*` wildcards), e.g. `https://*.gabvdl.xyz` (only that subdomain tree) or `https:` (any HTTPS origin). Note: CSP `frame-ancestors` uses host-pattern source expressions, not arbitrary regex — Caddy emits the header statically and the browser matches the embedding origin against it.

### Custom response headers (`.zipgoconfig.json` `headers`)
The same `securityHeaders(frameAncestors, custom)` handler carries the site's `headers` map, so custom headers apply to **file and proxy routes alike** (`fileHandler`/`proxyHandler` both pass `s.Config.Headers`). The map is *merged into* the defaults, never a replacement: each entry adds a header, or overrides the one default of that name and leaves the others in place. Two rules matter and both are load-bearing:
- **Case-insensitive merge** (`headerKey`): a custom name is matched against the existing keys with `EqualFold` and reuses that key's spelling, falling back to `http.CanonicalHeaderKey`. Canonicalising blindly would be a bug — Go's canonical form of `X-XSS-Protection` is `X-Xss-Protection`, so a site overriding it would land on a *second* map key and Caddy would send the header twice.
- **Empty value = delete**: the header is dropped from the `set` map *and* added to the handler's `delete` list, so it also removes one the file_server or upstream produced.

`sites.ValidateHeaders` (used by both `readConfig` — a hard error, like any malformed config — and `doctor.checkHeaders`) rejects non-token names, values with CR/LF (response-splitting), and two entries differing only in case (which header wins would otherwise depend on Go's map iteration order, making the emitted config unstable across reloads).

### Site routing
- **Domain mode**: `Host()` (e.g. `api.docs.rootDomain`) → that folder
- **Localhost mode**: single port `9000` with path routing `LocalhostPath()` = `/<domain>/<outer>/.../<leaf>` (trailing dots stripped). Routes sorted deepest-first so nested paths win

### Install scripts
The install scripts (`domains/zipgo.xyz/install/{linux,macos,windows}.sh`) are **generated files** — do not edit them directly. Edit the parts in `scripts/parts/` and regenerate with `make build-install-scripts` (or `make build`).

## Security defaults (`internal/builder`)

Everything here is on by default and documented in the README's *Security* section — keep the two in sync:

- **HTTPS-only + HSTS**: a site that isn't served on :80 (`httpAllowed` = `allowHttp` and no `password`) gets `Strict-Transport-Security: max-age=31536000` (`hstsValue`, no `includeSubDomains`) through `securityHeaders(…, hsts)`; `httpsOnly(s, stripPrefix)` decides, and localhost mode never sends it. A site overrides or deletes it through its `headers` like any default.
- **`strict_sni_host`** on the HTTPS server: the Host header must be the SNI host, else 421 — otherwise a client could present a public site's SNI (what a TLS-passthrough proxy or an edge geo-fence lets through) and ask for a locked or fenced host in the Host header. One cert per host, so browsers never coalesce.
- **Dotfiles are refused** (`dotfileRoute`, a `*/.*` path match = substring `/.` on the cleaned path, `/.well-known/*` exempt) before any file server, SPA fallback or custom 404 — through the `error` handler so a static site's `404.html` still answers.
- **No directory listing** unless `"browse": true` (never on an SPA).
- **Escaping symlinks are hidden** (`escapingSymlinks`: a link whose target leaves the site folder or enters a nested trailing-dot site — Caddy follows symlinks anywhere, so one could serve the cert store, the session key or a locked sibling); `zipgo deploy` also passes rsync `--safe-links`.
- **`rewrite` allowlist** (`ZIPGO_REWRITE_ALLOW`): unlisted upstream → `refusedUpstreamHandler` (403) + a log line; unset = unrestricted (back-compat).
- **Catch-all 421** on the HTTPS server for a Host with no route; **timeouts** `read_header_timeout: 15s`, `idle_timeout: 2m` on every content server (Caddy ≥ 2.11.6 adds 1-min idle read/write deadlines and a 16 KiB header cap itself); **trusted proxies** from `TrustedProxies()`.
- **Access log redaction**: the `json` encoder is wrapped in Caddy's `filter` encoder with a `query` filter deleting `gate.UnlockParam` from `request>uri`.
- Already there: Caddy's admin API disabled, metrics on loopback only, exact TLS subjects (no on-demand TLS), bcrypt cost 12, HMAC `__Host-` session cookies, per-IP + per-site login throttle, same-origin checks on the back-office API.
- **Supply chain**: `go.mod` pins Caddy and a `toolchain` line; CI (`.github/workflows/ci.yml`) runs `go vet`, the tests and `govulncheck` on every push and weekly; Dependabot groups the Go, Actions and Docker bumps; the release workflow builds with `-mod=readonly -trimpath` and actions pinned to commits; `docker/Dockerfile` verifies the binary against the release's `checksums.txt`, pins alpine by digest and runs as uid 1000 with the data dir at `/data` (`XDG_DATA_HOME`); `docker-compose.yml` drops every capability, `read_only` rootfs, `no-new-privileges`, pid/memory limits. Run `govulncheck ./...` before cutting a release.
